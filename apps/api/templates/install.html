PR Sentinel 安装 / 配置

安装说明 控制台 /health

1. 创建 GitHub App

  1. GitHub → Settings → Developer settings → GitHub Apps → New。
  2. Webhook URL：填 smee.io channel，或公网 API /webhooks/github。
  3. Webhook Secret：与环境变量 GITHUB_WEBHOOK_SECRET 完全一致（即使用 smee 也建议验签）。
  4. 权限：Contents Read、Pull requests Read & Write、Issues Read & Write（sticky comment）。
  5. 事件：至少勾选 Pull request。
  6. 记下 App ID，下载 Private Key（PEM）。

2. smee 本地转发

npx smee -u https://smee.io/YOUR_CHANNEL -t http://127.0.0.1:8000/webhooks/github

生产环境把 App Webhook 指到公网 API，无需 smee。

3. 环境变量（见 .env.example）

GITHUB_WEBHOOK_SECRET=...
GITHUB_APP_ID=...
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\n..."
# 或 GITHUB_APP_PRIVATE_KEY_PATH=./app.pem
REDIS_URL=redis://localhost:6379/0
ADMIN_TOKEN=请换成足够长的随机串   # 控制台 /jobs /retry 鉴权
OPENAI_API_KEY=                    # 可选；无则 rules-only
WEBHOOK_SKIP_VERIFY=false
USE_FIXTURES=false                 # 真机联调关 fixture

未设置 ADMIN_TOKEN 时，GET /jobs 与 POST /jobs/{id}/retry 返回 503。

4. 启动

docker compose -f deploy/docker-compose.yml up --build
# 控制台
open http://localhost:8000/console
curl http://localhost:8000/health

装 App 到测试仓 → 开 PR → Worker 写 sticky comment → 在控制台看任务 / 失败重试。

完整演示：仓库 docs/e2e-demo.md。
